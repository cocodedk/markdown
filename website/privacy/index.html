Privacy policy: Markdown

This policy is for Markdown, an Android app from Cocode. It explains what the app does with your information. Android knows the app by its package name, dk.cocode.markdown.

Effective 7 October 2026.

Summary

Markdown does not collect your personal data, and the app itself cannot connect to the internet. There is no account, no analytics (tracking of how you use the app), no advertising and no crash reports.

The app asks Android for no permissions. It opens a file only when you choose it or send it to the app, and it saves a file only when you tap Save.

What is collected

Nothing is collected, and the app sends no information about you to anyone. It works with two things, and only on your phone:

  • The text of the file you open or share, or the text you type in the editor. The app holds it in the phone's working memory so it can show it and let you edit it. If a file is larger than 2 MiB (2,097,152 bytes, a little more than 2 MB), the app does not open it and tells you it is too large.
  • The file's name, which Android gives the app. It is shown as the title at the top of the screen.

The app has no account. It uses no identifier for you or your phone, no location, no contacts and no usage statistics.

If you write to Cocode (see Contact), Cocode receives your message and your email address. That has nothing to do with the app.

Servers the app contacts

None. A server is a computer on the internet that an app can send information to or fetch information from. Markdown talks to no server.

  • Android lets an app use the internet only if the app has the internet permission. Markdown does not have it, and its code makes no network requests.
  • Markdown shows your document in a web view. That is the part of Android that draws web pages. Here it is set to load nothing from the internet, so a picture in a document is never fetched. It appears as the words [image: description] instead, using the picture's own description.
  • A link in a document is only an address until you tap it. When you tap one, Markdown passes the address (a web or an email address) to Android. Android opens it in the browser or mail app you use. That app contacts the link's server, not Markdown.
  • The About screen has buttons that open web pages on this website and on GitHub: "See the latest version", "Read the privacy policy", "Open the website", "See the source code on GitHub" and "Report a problem on GitHub". They work like a link in a document. Nothing opens until you tap a button. Then Markdown passes the address to Android, and Android opens it in your web browser. Your browser contacts that page's server, not Markdown. Markdown never checks for updates on its own.

This website is separate from the app. When you read this page, your browser fetches a stylesheet and a script for the Cocode page frame (the bars at the top and bottom of the page) from brand.cocode.dk. The page itself comes from GitHub Pages, GitHub's website hosting. Those requests come from your browser, not from the app.

Permissions

A permission is something Android asks you to allow before an app can use it, such as the camera or the internet. Markdown asks for none: no internet, no storage, no camera, no microphone, no location, no contacts and no notifications.

It can still open and save files, because you give it each file yourself:

  • When you tap Open, Android's own file picker (a screen where you choose a file) lets you pick one. Android then gives Markdown access to that one file.
  • When another app opens a file in Markdown, or shares a file or text to it, Markdown receives that file or text in the same way.
  • When you tap Save, Markdown writes to the file Android gave it, or to the place you choose in Android's file picker.

The app also tells Android which kinds of file it can open (Markdown and plain text), so Android offers it under "Open with". That is not a permission.

What stays on the phone

Markdown stores nothing of its own: no database, no settings file, no cache (saved copies kept for speed) and no history.

While the app runs, the text of the open file and the file's address are held in the phone's working memory. Changes you have not saved exist only there. If you tap Close editor with unsaved changes, the app asks "Discard your changes?", and choosing Discard throws them away. They are also gone when the app is closed.

The only thing Markdown writes is the file itself, and only when you tap Save. It goes to the file you opened or to the place you chose. That file is yours and stays where you put it. To delete it, use your file manager, the app you use to browse files.

Android can copy an app's data into a backup. Markdown turns that off, so none of it is copied into an Android backup.

Third parties

Markdown sends data to no third party, meaning no other company or service. It has no analytics, advertising or crash-reporting library. A library is ready-made code that an app includes.

The libraries it does include are Android's Jetpack and Compose (Google), Kotlin and its coroutines (JetBrains), and the open-source CommonMark and autolink libraries, which turn Markdown text into a page. They run inside the app. Because the app has no internet permission, none of them can connect to anything.

Other parts of Android and other apps take part when you use Markdown. Each has its own policy:

  • Android System WebView, the web view described above. In Markdown its scripts, file access and network loading are switched off.
  • The file picker, and the app that holds your file or sends it to Markdown: a file manager, a mail app or a cloud storage app (an app that keeps files online). A cloud storage app may download a file when you open it and upload it again after you save. That is that app, not Markdown.
  • The browser or mail app that opens a link you tap, in a document or on the About screen.
  • Your keyboard, when you type in the editor. Markdown has no keyboard of its own.

Your rights

Markdown collects no personal data, and Cocode receives none from it. So there is nothing to look up, correct or delete.

The General Data Protection Regulation (GDPR) gives you the right to ask what personal data is held about you, to have it corrected or deleted, and to complain. If you are in doubt, write to bb@cocode.dk. You can also complain to the Danish Data Protection Agency, Datatilsynet.

Contact

Write to Cocode (Babak Bandpey) at bb@cocode.dk with questions about the app or this policy. You can also open an issue on GitHub. Issues there are public, so leave out anything private.

Changes

If this policy changes, the date at the top changes and this section says what is new. Earlier versions are in the project's history on GitHub.
